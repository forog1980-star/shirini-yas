## ۱. هدف جلسه بعد
ادامه رفع قطعی عدم نمایش لوگو و تصاویر محصولات در GitHub Pages؛ تصاویر محصول باید داخل خود مخزن قرار بگیرند و نمایش آن‌ها به میزبان خارجی وابسته نباشد. پس از اصلاح، build و آزمون واقعی مرورگر انجام شود و نتیجه برای تأیید اولیه مالک در GitHub ارائه گردد.

- سایت در زیرمسیر /shirini-yas/ منتشر می‌شود.
- در main، مسیر لوگو در src/App.tsx و آواتار در src/data/initialData.ts هنوز /assets/aistudio/photo_2026-10-11_20-52-21_08dc8782.jpg است؛ مسیر مطلق برای این استقرار نادرست است.

## ۳. چرا کار قبلی مشکل را حل نکرد؟
۱. اصلاح مسیر لوگو فقط در شاخه PR شماره ۳ انجام شده و هنوز در main نیست؛ بنابراین سایت اصلی آن تغییر را دریافت نکرده است.
۲. عکس‌های محصول هنوز از میزبان خارجی Unsplash می‌آیند. ویژگی‌هایی مانند decoding="async" یا referrerPolicy عکس‌ها را محلی نمی‌کنند.
۳. اجرای موفق GitHub Actions فقط موفقیت ساخت/انتشار را نشان می‌دهد؛ آزمون دیداری لوگو و تصاویر در مرورگر کاربر انجام نشده و کاربر همچنان عدم نمایش را گزارش کرده است.

## ۴. دستور کار فنی جلسه بعد

### مرحله A — بررسی و Recovery Point
- ابتدا اسناد پروژه، DAILY_LOG.md، TECHNICAL_REPORT.md، سند رسمی محصول و همین نقطه شروع خوانده شوند.
- وضعیت لحظه‌ای main، شاخه PR شماره ۳، PRها، commitها و workflowها دوباره از GitHub خوانده شود.
- آخرین HEAD شاخه اصلاحی و فایل‌های درگیر بازخوانی شوند؛ فرض نشود اطلاعات این سند بدون بررسی همچنان تازه است.
- پیش از هر تغییر، Recovery Point تازه از HEAD شاخه کاری ایجاد و با compare تأیید شود.

### مرحله B — دارایی‌های تصویر
- از مالک، عکس‌های واقعی و مورد تأیید محصولات دریافت یا اجازه استفاده از تصاویر جایگزین مشخصاً اخذ شود.
- لوگوی مرجع فعلی حفظ شود؛ لوگوی تازه یا تصویر نامرتبط ساخته/جایگزین نشود.
- تصاویر محصول پس از کنترل فرمت، ابعاد، حجم و کیفیت در public/assets/products/ قرار گیرند.
- تا زمانی که تصاویر واقعی/مجاز مشخص نشده‌اند، عکس تصادفی را به‌عنوان محصول یاس ثبت نکنید.

### مرحله C — اصلاح حداقلی
- مسیر لوگو و آواتار با import.meta.env.BASE_URL یا راهکار استاندارد سازگار با Vite base اصلاح شود.
- URLهای خارجی تصاویر محصول با مسیرهای داخلی و پایدار جایگزین شوند.
- همه مصرف‌کننده‌های product.photos، از جمله کارت، گالری و modal جزئیات بررسی شوند.
- تمام ارجاع‌های تصویر، favicon، تصویر پیش‌فرض، لوگو و آواتار جست‌وجو شوند.
- از بازنویسی گسترده App.tsx یا تغییر غیرضروری هسته خودداری شود.

### مرحله D — بررسی و تست
- قبل/بعد: فهرست فایل‌ها، حجم تصاویر و ساختار پوشه‌ها ثبت شود.
- npm ci (در صورت وجود lockfile معتبر) یا روش نصب تثبیت‌شده پروژه اجرا شود.
- npm run lint و npm run build اجرا و خروجی واقعی ثبت شود.
- محتویات dist و URLهای نهایی تصاویر بررسی شوند.
- در Preview یا محیط انتشار، بازشدن مستقیم هر فایل تصویر و نمایش لوگو/تصاویر در صفحه اصلی و جزئیات بررسی شود.
- مرورگر دسکتاپ و گوشی تست شوند؛ خطاهای Network و Console ثبت شوند.
- هر تست اجرا‌نشده صریحاً «انجام نشده» نوشته شود.

### مرحله E — Review و ارائه برای تأیید
- diff، مسیرها، وابستگی‌ها و حجم فایل‌های تغییرکرده بازبینی شوند.
- گزارش روزانه و فنی با نتیجه واقعی تست تکمیل شوند.
- PR برای تأیید اولیه آماده شود؛ main تا اجازه صریح مالک ادغام نشود.
